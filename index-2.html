⚡ Quick Start: Deploy in 30 Minutes

✅ Ready to Go: Your platform is production-ready. Follow these 6 steps to deploy to AWS.

Prerequisites

  • AWS Account with EC2 and RDS access
  • SSH key pair created
  • Domain name (e.g., api.eascrow.io)
  • Environment variables documented
Step 1: Launch EC2 Instance (5 min)

Log into AWS Console → EC2 → Launch Instance

AMI: Ubuntu 22.04 LTS
Instance Type: t3.small
Storage: 30GB
Security Group: Allow 22, 80, 443
Step 2: Create RDS Database (5 min)

Launch → RDS PostgreSQL 15

Instance: db.t3.micro
Storage: 20GB
DB Name: escrow_prod
Public Accessible: No
Backup: 7 days retention
Step 3: SSH into EC2 Instance (2 min) 
ssh -i your-key.pem ubuntu@your-instance-ip
Step 4: Clone and Run Deployment (10 min) 
git clone https://github.com/yourusername/escrow-mvp.git
cd escrow-mvp
bash deploy.sh

The script will:

  • Install Node.js, PostgreSQL, Nginx
  • Install dependencies
  • Set up SSL certificate
  • Configure application
  • Start services
Step 5: Configure DNS (2 min)

Point your domain to EC2 instance IP

A Record: api.eascrow.io → your-instance-ip
Step 6: Verify Deployment (2 min) 
curl https://api.eascrow.io/api/health
# Expected: {"status":"ok"}

✅ You're Live!

Your platform is now running at https://api.eascrow.io

Run every morning before market opens at 8:00 AM:

  • API health check returns "ok"
  • Application status is "online"
  • Database connection successful
  • Disk usage < 70%
  • Memory usage < 70%
  • No ALARM state in CloudWatch

# Run this every morning

psql $DATABASE_URL -c "SELECT 1"

📊 Monitoring & Alerting Setup

⚠️ Critical: This setup takes ~3 hours but is essential for production operations.

What We're Monitoring

Category Metrics Target
System Health CPU, Memory, Disk, Database <80% usage
API Performance Response time, Error rate, Uptime <100ms, <0.1%, 99.9%
Business Daily transactions, Revenue, Disputes Track growth
Security Failed auth, Unauthorized access Monitor anomalies

Phase 1: AWS CloudWatch (15 min)

Enable CloudWatch Logs 
# SSH into your EC2 instance
ssh -i your-key.pem ubuntu@your-instance-ip

# Install CloudWatch agent
wget https://s3.amazonaws.com/amazoncloudwatch-agent/ubuntu/amd64/latest/amazon-cloudwatch-agent.deb
sudo dpkg -i -E ./amazon-cloudwatch-agent.deb

Phase 2: Create Alarms (30 min)

CloudWatch Alarms Setup 
# Create CPU alarm
aws cloudwatch put-metric-alarm \
  --alarm-name "EscrowAPI-HighCPU" \
  --alarm-description "CPU usage exceeds 80%" \
  --metric-name CPU_IDLE \
  --namespace EscrowAPI \
  --statistic Average \
  --period 300 \
  --evaluation-periods 2 \
  --threshold 20 \
  --comparison-operator LessThanThreshold \
  --alarm-actions arn:aws:sns:us-east-1:YOUR_ACCOUNT_ID:escrow-alerts

Phase 3: SNS Notifications (20 min)

Create SNS Topic 
aws sns create-topic --name escrow-alerts

# Subscribe email
aws sns subscribe \
  --topic-arn arn:aws:sns:us-east-1:YOUR_ACCOUNT_ID:escrow-alerts \
  --protocol email \
  --notification-endpoint ops@eascrow.io

Phase 4: Dashboards (30 min)

Create CloudWatch Dashboard showing:

  • System resources (CPU, Memory, Disk)
  • API metrics (Response time, Error rate)
  • Database health (Connections, Latency)
  • Business metrics (Daily transactions, Revenue)

Access Your Dashboard

https://console.aws.amazon.com/cloudwatch/home?region=us-east-1#dashboards:

Success Metrics to Track

Metric Target Alert Threshold
API Uptime 99.9% Health check fails
Response Time (p95) <100ms >200ms
Error Rate <0.1% >0.5%

🔔 Alert Response Procedures

🚨 Critical Alerts: Require response within 5 minutes

🔴 CRITICAL: Health Check Failing

Immediate Action (within 2 minutes) 
# Test directly
curl -v https://api.eascrow.io/api/health

# Check app status
pm2 status

# If not online, restart
pm2 restart escrow-api

# Wait 30 seconds, then verify
curl -s https://api.eascrow.io/api/health | jq .
⏱️ If not resolved in 5 minutes: Page L2 engineer

🔴 CRITICAL: Database Down

Immediate Action 
# Check RDS status
aws rds describe-db-instances \
  --db-instance-identifier escrow-prod-db \
  --query 'DBInstances[0].DBInstanceStatus'

# If "rebooting", wait 5 minutes
# If "failed", trigger reboot
aws rds reboot-db-instance \
  --db-instance-identifier escrow-prod-db

# Wait for available status
aws rds wait db-instance-available \
  --db-instance-identifier escrow-prod-db

# Restart application
pm2 restart escrow-api

🟠 HIGH: High CPU/Memory

Action 
# Check process
top -bn1 | head -20

# Monitor with PM2
pm2 monit

# Restart if needed
pm2 restart escrow-api

# Monitor for 10 minutes
watch -n 5 'top -bn1 | grep Cpu'

🟡 MEDIUM: High Disk Usage

Action 
# Check disk
df -h

# Clean old logs
rm -f ~/.pm2/logs/*-error.log.*
rm -f ~/.pm2/logs/*-out.log.*

# Verify
df -h

Alert Response Matrix

Alert Severity Response Time First Action

Database Down 🔴 CRITICAL 5 min Reboot RDS
High CPU 🟠 HIGH 15 min Identify process

🔵 AWS S3 Deployment (Recommended)

✅ Best for Production
Global CDN • HTTPS • Auto-scaling • $5/month • Zero maintenance
Step 1: Create AWS Account

Visit https://aws.amazon.com/ and create a free account if you don't have one

Step 2: Install AWS CLI 
# macOS
brew install awscli

# Linux
sudo apt-get install awscli

# Windows (Python required)
pip install awscli

# Verify installation
aws --version
Step 3: Configure AWS Credentials 
aws configure

# You'll be prompted for:
# AWS Access Key ID: [your-access-key]
# AWS Secret Access Key: [your-secret-key]
# Default region: us-east-1
# Default output format: json

Get credentials from: AWS IAM Console

Step 4: Create S3 Bucket 
# Create bucket (choose unique name)
aws s3 mb s3://escrow-docs --region us-east-1

# Enable static website hosting
aws s3 website s3://escrow-docs \
  --index-document index.html \
  --error-document index.html

# Make bucket public
aws s3api put-bucket-policy --bucket escrow-docs \
  --policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::escrow-docs/*"
    }]
  }'
Step 5: Upload Files 
# Upload HTML file
aws s3 cp index.html s3://escrow-docs/index.html \
  --content-type text/html

# Or upload entire directory
aws s3 sync ./ s3://escrow-docs/ \
  --include "*.html" \
  --include "*.css" \
  --include "*.js"
Step 6: Access Your Website

Your documentation is now live at:

http://escrow-docs.s3-website-us-east-1.amazonaws.com/

Note: Replace escrow-docs with your bucket name

✅ S3 Deployment Complete!

  • Website is publicly accessible
  • Files are cached globally via S3
  • Auto-scales for traffic
  • Cost: ~$5/month

🔒 (Optional) Add CloudFront for HTTPS

# Create CloudFront distribution
aws cloudfront create-distribution \
  --origin-domain-name escrow-docs.s3.amazonaws.com \
  --default-root-object index.html

# Then point your domain (docs.eascrow.io) to CloudFront via DNS CNAME
# Cost: CloudFront charges ~$0.085 per GB transferred

🟢 Nginx Deployment (On Existing Server)

💡 Good for: Keeping docs with your API server • No additional costs
SSH into Your Server 
ssh -i your-key.pem ubuntu@api.eascrow.io
Create Documentation Directory 
sudo mkdir -p /var/www/docs
cd /var/www/docs
Copy HTML File 
sudo cp ~/escrow-mvp/docs/index.html /var/www/docs/
Update Nginx Configuration 
sudo nano /etc/nginx/sites-enabled/escrow

# Add this location block:
location /docs {
    alias /var/www/docs/;
    index index.html;
    try_files $uri $uri/ /docs/index.html;
}
Restart Nginx 
sudo nginx -t              # Test config
sudo systemctl reload nginx # Reload
✅ Done!
Access at: https://api.eascrow.io/docs/
